# 管理页验收清单

修改管理页（`src/web/page.html`、`src/web/app/`、`src/web/server.ts` 里提供页面的部分）时逐条核对。每条写明界面必须保持的行为、原因，以及覆盖它的测试；标“人工”的条目没有自动化测试，需要在浏览器里看。实现说明见 [技术文档的“管理页”](../docs/architecture.md#管理页)。

测试文件：`web-ui.test.ts` 简写为 UI，`web.test.ts` 简写为 Web。

## 安全

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 页面要带正确的 token；接口要带 `x-endpoints-token`；`Host` 必须是 `127.0.0.1:端口`；修改操作只接受 JSON | 防止本机其他网页伪造请求、防止 DNS 重绑定 | Web“管理页的防护” |
| 脚本、样式和第三方模块不要 token，但检查 `Host`；只提供 `src/web/app/` 这一层的 `.js`、`.css` 和 `VENDOR` 里的文件 | 这些文件不含密钥；不能借路径读到别的文件 | Web“页面的脚本、样式和第三方模块……” |
| CSP 不带 `'unsafe-inline'`，内联脚本只按哈希放行 import map | 收紧脚本和样式来源 | Web“CSP 只放行……” |
| 接口和页面都不回显密钥 | 密钥只写不读 | Web“添加服务、写密钥……” |
| 密钥框是 `type="password"`、`autocomplete="one-time-code"`，带 `data-1p-ignore` 等属性 | 免得浏览器和密码管理器把网站密码填进来；密码框忽略 `off`，`new-password` 会弹出生成密码 | UI“保存失败时保留已填内容……” |

## 请求和状态

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 修改操作排队，前一个结束后才发下一个 | 页面上的操作按点击顺序生效 | UI“修改操作排队执行……” |
| 按 `X-Endpoints-Seq` 丢掉先发后到的旧状态，采用长时间刷新带回的新状态 | 旧响应不能覆盖新状态；刷新先发但状态最后生成 | UI“先发后到的旧状态被丢弃……”，Web“响应带递增的编号……” |
| 开关在请求期间按要切换到的值显示，失败时拨回原样并在顶部显示原因 | 开关和服务端状态一致 | UI“停用服务后它留在原处……”“工具栏的开关……失败时拨回原样” |
| 后台刷新、状态更新不冲掉服务表单、密钥框、详情面板表单里没保存的输入，也不抢走焦点 | 用户正在输入 | UI“后台刷新期间填的表单、密钥和焦点都保留”“详情面板的生效参数……” |
| 打开页面时在后台刷新所有启用且有密钥的服务；在左栏重新启用服务成功后刷新这个服务；后台刷新失败不弹顶部提示 | 目录缓存可能过时 | UI“停用的服务排在下面……”“重新启用服务后在后台刷新它的目录” |
| 刷新期间（包括后台刷新）“刷新目录”按钮显示“刷新中…”且不能点 | 不重复刷新 | UI“先发后到的旧状态被丢弃……” |
| 刷新失败时顶部显示“刷新失败：原因”，服务页头下方同样原因的错误条不重复显示，关掉顶部提示后再显示 | 同一原因不显示两遍 | 人工 |
| 顶部错误可以用 × 关掉；切换服务或点“添加服务”时清掉 | | 人工 |
| 配置读不了时显示 `loadError`；注册出错时显示 `syncError` 并提示 `/reload`；没有密钥时提示并给“去设置”按钮 | | 人工 |
| 页面加载失败时提示在 pi 里重新运行 `/endpoints` | | 人工 |

## 左栏

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 停用的服务排在启用的下面，中间有分隔线；组内保持配置文件里的顺序 | | UI“停用的服务排在下面……” |
| 打开页面时默认选中第一个启用的服务 | | UI“停用的服务排在下面……” |
| 网址带 `service` 参数且服务存在时选中它的“模型”页，否则照旧 | `/endpoints` 在有新版时带上服务名 | UI“网址带 service 参数……”“service 参数指向不存在的服务……” |
| 切换开关后服务留在原处，刷新页面后再挪 | 方便改回来 | UI“停用服务后它留在原处……” |
| 服务的 `updates` 不为空时，服务名旁显示“有新版” | 发现新版 | UI“有待换的新版时，服务名旁显示角标” |
| 服务行是 `div role="button"`，Enter 和空格可以选中；开关的点击不触发选中 | 按钮里不能放开关 | 人工 |
| 版本号显示在左下角，npm 上有新版时显示绿色箭头，点击打开 Release 页面；检查失败时不显示 | | UI“显示版本号……” |

## 模型页

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 开关关着且 `updates` 不为空时，顶部横幅列出“N 个已启用模型有新版：a → b”，带“换成新版”和“开启自动替换” | 发现新版 | UI“开关关着、有待换的新版时显示横幅……”“开启自动替换……” |

| 换服务时清掉协议、`owned_by` 和前缀筛选，保留搜索和“显示隐藏模型” | 这些选项按服务各自的模型生成 | 人工 |
| 分组按 gpt、claude、gemini、grok 在前，其余按字母序；组内按版本号从新到旧；分组的折叠按“服务名/前缀”记录 | | UI“版本号和前缀”；折叠：人工 |
| 每个分组一张表，各表列宽相同，表头只在第一张 | | 人工 |
| 空列表的文案：没有目录时按有无密钥提示“刷新目录”；“已启用”页没有启用的模型时显示“还没有启用模型”；否则“没有符合条件的模型” | | UI“选中的前缀数量变成 0 时……”；其余：人工 |

## 详情面板

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 生效的参数、启用开关、星标按最新状态显示 | 后台刷新和“每系最新”会改模型 | UI“详情面板的生效参数跟着最新状态更新……” |
| 模型从状态里消失时，开关按未启用显示，星标清空 | 旧星标可能代表被换掉的默认模型 | UI“详情里的模型从状态里消失时……” |
| 测试消息的结果只显示在发出时的模型上 | 中途可能换了模型 | UI“测试消息的结果只显示在发出时的模型上” |
| 输入法选字时（`isComposing` 或 `keyCode` 229）和焦点在输入框里时，Esc 不关闭 | 免得误触丢掉输入 | UI“输入法选字时的 Esc 不关闭……” |
| 有未保存的修改时，Esc、遮罩和 × 关闭前都先确认；测试消息的档位不算修改；保存成功后不再询问 | | UI“输入法选字时的 Esc……”“保存手动设置……” |
| 错误和测试结果显示在底部按钮上方，不随面板内容滚动；操作失败的原因也显示在面板里；成功后清掉错误 | 面板盖住了页面顶部 | UI“保存手动设置……”“操作失败的原因也显示在详情面板里” |
| 上下文和最大输出用文本框，接受 1000000、1,000,000、200K、1M；认不出时报错不保存 | number 框读不出 1M、1,000,000 | UI“保存手动设置……”“parseCount 接受……” |
| 思考档位空数组回显 none；只填 none 时保存为空数组 | 再次保存时不丢 | 人工 |
| 价格只填部分字段时其余补 0 | | 人工 |
| 模型带 context-1m beta 时，上下文的说明提示超过 200000 自动带上 beta | | 人工 |
| compat 标签显示每个字段的来源，手动删掉的字段带删除线 | | 人工 |
| 测试消息可选思考档位（`levels` 去掉 `off`），结果显示实际发出的档位 | | 人工 |
| “清除手动设置”在没有手动设置时不能点 | | 人工 |
| 切到“服务设置”页时关闭面板 | | 人工 |
