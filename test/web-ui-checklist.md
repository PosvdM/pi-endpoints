# 管理页验收清单

修改管理页（`src/web/page.html`、`src/web/app/`、`src/web/server.ts` 里提供页面的部分）时逐条核对。每条写明界面必须保持的行为、原因，以及覆盖它的测试；标“人工”的条目没有自动化测试，需要在浏览器里看。实现说明见 [技术文档的“管理页”](../docs/architecture.md#管理页)。

测试文件：`web-ui.test.ts` 简写为 UI，`web.test.ts` 简写为 Web。

## 安全

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 页面要带正确的 token；接口要带 `x-endpoints-token`；`Host` 必须是 `127.0.0.1:端口`；修改操作只接受 JSON | 防止本机其他网页伪造请求、防止 DNS 重绑定 | Web“管理页的防护” |
| 脚本、样式和第三方模块不要 token，但检查 `Host`；只提供 `src/web/app/` 这一层的 `.js`、`.css` 和 `VENDOR` 里的文件 | 这些文件不含密钥；不能借路径读到别的文件 | Web“页面的脚本、样式和第三方模块……” |
| CSP 不带 `'unsafe-inline'`，内联脚本只按哈希放行 import map | 收紧脚本和样式来源 | Web“CSP 只放行……” |
| 接口和页面都不回显密钥 | 密钥只写不读 | Web“添加服务、写密钥……” |
| 密钥框是 `type="password"`、`autocomplete="one-time-code"`，带 `data-1p-ignore`、`data-bwignore`、`data-lpignore` | 免得浏览器和密码管理器把网站密码填进来；密码框忽略 `off`，`new-password` 会弹出生成密码 | UI“保存失败时保留已填内容……” |

## 请求和状态

| 行为 | 原因 | 覆盖 |
|---|---|---|
| 修改操作排队，前一个结束后才发下一个 | 页面上的操作按点击顺序生效 | UI“修改操作排队执行……” |
| 刷新（手动、打开页面、重新启用服务）先等调用前已排队的修改操作完成再发；刷新期间后来的修改操作照常发出，不等刷新 | 刷新按磁盘上的配置执行“每系最新”，越过还没提交的修改（如刚关掉的开关）会替换模型和 pi 默认模型 | UI“手动刷新等此前排队的写操作完成再发……”“重新启用服务后的后台刷新也排在此前的写操作后面” |
| 刷新等待期间，同一服务排在它前面的修改只要有一个失败，就取消这次刷新，顶部保留那个修改的错误；其他服务的修改失败不影响 | 修改失败时磁盘上仍是旧配置，照样刷新会按旧配置替换模型和 pi 默认模型，还会清掉失败的提示 | UI“同一服务排在刷新前面的修改失败时取消刷新……”“其他服务的修改失败不影响刷新” |
| 刷新取消时顶部显示那个修改的错误，编号不变：期间别的修改成功清掉了它时恢复，顶部已有更新的错误时保留更新的 | 用户要看到刷新为什么没发 | UI“刷新取消时恢复被别的修改清掉的原错误……”“刷新取消时顶部已有更新的错误就保留它” |
| 手动刷新始终带 `latestPerFamily`，以下各项都为开时才为 `true`：两份快照里服务的值和待提交值、工具栏复选框的实际勾选状态（模型页没挂载时不算）、这个服务最后一次开关写入没有失败 | 前端时序挡不住所有交错，服务端按它判断是否替换；拿不准用户意图时不替换，漏换下次会补上，误换会改掉 pi 默认模型 | UI“手动刷新始终带上 latestPerFamily……”“开关写入失败后、还没有成功的写入前……”“复选框实际没勾选时……”“按着指针时用键盘关掉开关……”（两条）“按下‘刷新目录’期间关闭失败……” |
| 自动刷新（打开页面、重新启用服务后）在本次打开页面期间没动过这个服务的开关时不带 `latestPerFamily`，动过时按手动刷新的规则取值 | 页面拿到的状态可能落后于磁盘（另一个 pi 刚打开了开关），带 `false` 会漏换 | UI“自动刷新在没动过‘每系最新’开关时不带 latestPerFamily……”“重新启用服务后的后台刷新也排在此前的写操作后面” |
| 刷新成功只清掉发起刷新时页面上显示的那条顶部错误 | 刷新期间出现的错误（如关闭开关失败）用户可能还没看到 | UI“按下‘刷新目录’期间关闭失败……” |
| 响应一到就按 `X-Endpoints-Seq` 采用状态、分配错误编号；成功回调、导航和表单重填读最新采用的状态（`store.latest()`） | 按着指针时组件拿到的快照可能还是旧的，按它重填会写回旧值、选中已删除的服务 | UI“详情面板保存后按服务端返回的值重填……”“服务表单保存后按服务端返回的地址重新挂载”“删除第一个服务后选中剩下的第一个服务”“错误的先后按响应到达的时刻算……” |
| 初始状态同样按编号采用，按最新采用的服务列表选第一个服务；已采用但还没发布时页面按加载中显示 | 按着指针时初始状态返回，不能停在“添加服务” | UI“初始状态在按着指针时返回……” |
| 同一开关连续切换时，每次提交只清自己的待提交记录，开关显示最后一次切换的值 | 先完成的请求不能让开关跳回去 | UI“同一开关连续‘开 → 关’……” |
| 指针按下期间推迟发布给组件重画，松开后（等这次点击处理完）再发布最新的快照；状态照常立即采用 | 后台刷新会增删或挪动行，按下时换掉了行，点击就落空 | UI“按着指针时推迟采用后台刷新带来的状态……”“同一次按下期间到达高编号的修改……” |
| 按 `pointerId` 跟踪，多个指针时全部松开才放行；`pointercancel`、`lostpointercapture`、窗口失去焦点、指针移动或进入页面时 `buttons` 为 0、按住超过 1 秒（`HOLD_LIMIT`）时也放行，超时放行时清掉这一轮的指针记录 | 漏掉松开事件时页面不能一直不更新；留着记录的话下次点击松开时不会放行 | UI“多个指针按下时，全部松开才重画”“…时放行”“按住超过上限时放行”“超时放行后，换一个指针点击时松开即放行” |
| 按 `X-Endpoints-Seq` 丢掉先发后到的旧状态，采用长时间刷新带回的新状态 | 旧响应不能覆盖新状态；刷新先发但状态最后生成 | UI“先发后到的旧状态被丢弃……”，Web“响应带递增的编号……” |
| 开关在请求期间按要切换到的值显示，失败时拨回原样并在顶部显示原因 | 开关和服务端状态一致 | UI“停用服务后它留在原处……”“工具栏的开关……失败时拨回原样” |
| 后台刷新、状态更新不冲掉服务表单、密钥框、详情面板表单里没保存的输入，也不抢走焦点 | 用户正在输入 | UI“后台刷新期间填的表单、密钥和焦点都保留”“详情面板的生效参数……” |
| 新版横幅以服务为 key，A 正在“换成新版”时切到 B，B 的按钮照常可用 | “替换中…”只属于发起替换的服务 | UI“A 正在‘换成新版’时切到 B……” |
| 打开页面时在后台刷新所有启用且有密钥的服务；在左栏重新启用服务成功后刷新这个服务；后台刷新失败不弹顶部提示 | 目录缓存可能过时 | UI“停用的服务排在下面……”“重新启用服务后在后台刷新它的目录”；失败不弹提示：人工 |
| 刷新期间（包括后台刷新）“刷新目录”按钮显示“刷新中…”且不能点 | 不重复刷新 | UI“先发后到的旧状态被丢弃……” |
| 刷新失败时顶部显示“刷新失败：原因”，服务页头下方同样原因的错误条不重复显示，关掉顶部提示后再显示 | 同一原因不显示两遍 | 人工 |
| 顶部错误可以用 × 关掉；切换服务或点“添加服务”时清掉 | | 人工 |
| 配置读不了时显示 `loadError`；注册出错时显示 `syncError` 并提示 `/reload`；没有密钥时提示并给“去设置”按钮 | | 人工 |
| 页面加载失败时提示在 pi 里重新运行 `/endpoints` | | 人工 |
